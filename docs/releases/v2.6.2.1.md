# v2rayF v2.6.2.1

Reliability hardening after v2.6.2.0 — fixes the Android TUN probe blind spot and expands push routing.

## Critical fix

v2rayF is **VPN-disallowed** on Android (prevents routing loops). v2.6.2.0's TUN health probe used default-route HTTP, which tested **clearnet**, not the path WhatsApp/Telegram use. v2.6.2.1 probes through the active VPN `Network` via `Network.OpenConnection()`.

## Added

- Signal, Slack, Apple push suffixes (desktop TUN)
- WhatsApp edge + Telegram API push hosts (Android explicit routes)
- Messaging `domain_suffix → proxy` route rule on Android TUN
- VPN re-establish when App Network bypass list or IPv6 block flag changes
- One-time battery optimization exemption prompt (Android)

## Changed

- Tun-only failures require **2** consecutive misses before soft recovery
- Network callback: VPN transport only, **5s** throttle
- Runtime refresh retries with DoH when Connect would

## Verify

1. Connect → force-stop WhatsApp → reopen (background v2rayF) — works without Disconnect
2. Change App Network Direct while connected → reconnect applies new bypass
3. Notifications: WhatsApp, Telegram, Discord, Signal (desktop TUN)
