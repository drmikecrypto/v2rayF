# v2.6.3.4

## Why

After lock → unlock while Connected, system internet died until Disconnect+Connect. Wake resume treated localhost SOCKS + VpnService Network as healthy even when the TUN app-path was dead, then only called `ReportVpnReady`. When soft recovery did run, SessionResume used `forceRebind: false` (hash no-op, same fd). Unlock without opening v2rayF often never fired resume at all.

## Fixes

- Resume early-success requires `IsResumePathHealthy` (live path and **not** TunWeak).
- SessionResume `EstablishVpnAsync(..., forceRebind: true)` when 90s rebind throttle allows; otherwise still `RefreshRuntime` with current fd.
- VpnService registers `USER_PRESENT` + `SCREEN_ON` → `NotifySessionRecovery` (existing 5s throttle).
- Connect / IG MQTT exclusions / Meta QUIC shove / fail-closed-on-missing-VPN unchanged.
