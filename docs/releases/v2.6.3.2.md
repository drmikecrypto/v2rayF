# v2.6.3.2

## Why

v2.6.3.1 fail-closed Connect on any TUN HTTPS miss. gen204/FCM through VpnService often fails (cold dial, censorship, unvalidated VPN) while the same config works in other apps and localhost SOCKS is healthy — Connect then refused every server.

## Fixes

- Fail-closed **only** when Android reports no VPN Network (`TunVpnMissingMs = -2`).
- VPN present + gen204/FCM miss (`-1`) → Connected with weak-TUN tip; soft recovery still rebinds.
- `VerifyLivePath` succeeds on SOCKS when VPN exists (missing Network still fails).
- Probe: `ReportVpnReady` before HTTPS; shared remaining timeout across URLs.
- Notify VPN ready before StartAsync on Android.

## Verify

```powershell
dotnet test src/v2rayF.Core.Tests/v2rayF.Core.Tests.csproj -c Release
```

On device: Connect a config that works in v2rayNG — must reach Connected (not TUN path failed). Chrome/system apps should load; if TUN tip appears, soft recovery may rebind without tearing Connect.
