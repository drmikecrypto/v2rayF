## Why

After 2.6.2.17, Connect often reached SOCKS OK then tore down the VPN with:

> HTTP proxy 10809 probe timed out

Same class of false TIMEOUT as TUN in 2.6.2.14: a secondary localhost probe failed while the tunnel already worked. Test All still under-warmed cold REALITY (single cold GET after short port wait).

- Connect gate hard requirement is **SOCKS only**; Android HTTP `10809` is advisory (status tip when weak)
- HTTP probe parity with SOCKS: connect timeout ≥8s, Vision/REALITY single gen204, warmup after SOCKS
- Test All / rank: warm-then-measure; Reality/Vision core-ready wait **5s**

Live TUN routing unchanged.
